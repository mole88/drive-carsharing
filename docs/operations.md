# Запуск и обслуживание

## Локальный запуск

Из корня проекта: `./start.ps1`. Скрипт использует `.venv`, применяет миграции и запускает приложение на `127.0.0.1:8000`.

- `/health` — процесс отвечает.
- `/ready` — соединение с БД работает, применена текущая миграция; иначе HTTP 503.
- `/docs` — документация API в режиме development.

## Резервное копирование SQLite

```powershell
.\.venv\Scripts\python.exe -m app.maintenance backups\drive-2026-09-16.db
```

Команда использует SQLite Backup API и проверяет целостность результата. Существующий файл никогда не перезаписывается. Запускайте команду по своему графику, храните копии вне сервера с ограниченным доступом: они содержат аккаунты и историю поездок. Автоматическое расписание пока не настроено.

Для восстановления остановите все процессы приложения, сохраните текущую БД отдельной копией, восстановите нужную копию как `carsharing.db`, затем запустите `start.ps1`. Восстановление возвращает всё состояние на момент копирования. Проверяйте восстановление отдельно от рабочей БД; не заменяйте открытый файл БД.

## Серверный запуск

Настройки `.env`:

```dotenv
ENVIRONMENT=production
COOKIE_SECURE=true
ALLOWED_HOSTS=["drive.example.com","127.0.0.1"]
SECRET_KEY=your-unique-random-secret-with-at-least-32-characters
DATABASE_URL=sqlite:////data/carsharing.db
```

Замените домен и секрет. Перед приложением нужен HTTPS reverse proxy. Приложение проверяет Host и отвергает небезопасную конфигурацию production. Адрес `127.0.0.1` в списке нужен для внутренней проверки здоровья. Uvicorn не следует публиковать напрямую; доверять forwarded-заголовкам следует только от своего proxy.

SQLite подходит для одного экземпляра сервиса с постоянным диском. Для нескольких серверов нужна общая БД и проверка на целевой СУБД; PostgreSQL в текущей среде не тестировался.

## Docker (конфигурация подготовлена, сборка здесь не проверена)

Docker в текущем окружении не установлен. После установки:

```sh
docker compose build
docker compose run --rm app python -m alembic upgrade head
docker compose run --rm app python -m app.cli seed
docker compose up -d
docker compose exec app python -m app.cli admin admin@example.com
```

Приложение работает от непривилегированного пользователя. Данные хранятся в именованном volume. Миграции запускаются отдельно до сервиса. Секреты и локальная БД не копируются в образ. `seed` нужен только для демонстрационного автопарка; реальные машины добавляются через кабинет администратора.

## Диагностика

Ответы содержат `X-Request-ID`; необработанная ошибка записывается в серверный лог с тем же идентификатором. Клиент не получает traceback. API-ответы запрещено кэшировать. Не публикуйте серверные логи или `.env`.

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app tests migrations
.\.venv\Scripts\python.exe -m alembic check
.\.venv\Scripts\python.exe -m pip check
```

### Активная аренда, из которой не выйти

У одной учётной записи не больше одной незавершённой поездки, поэтому активная
аренда блокирует новую бронь ответом 409. Пока с последней активности прошло
меньше `STALE_TRIP_MINUTES` (90 минут), завершить её можно игрой: там известно
наигранное время. Видимая страница игры посылает heartbeat раз в 30 секунд,
в том числе на паузе. После 90 минут без подтверждения сервер автоматически
завершает поездку: фоновый worker проверяет аренды каждые 30 секунд, запросы
каталога и аренды также запускают очистку. В миграции `0009` старые поездки без
`last_activity_at` используют `started_at` (или `created_at`). Результат игры
и рекорд не создаются; стоимость составляет одну минуту тарифа, история
сохраняется, журнал получает `rental.expired`. Квитанция показывает эту же минуту.
Heartbeat завершённой или просроченной поездки не может снова занять машину.
Есть также два ручных пути — `POST
/api/rentals/{id}/return` (владелец, списывается одна минута тарифа) или `POST
/api/admin/rentals/{id}/close` (администратор; требует `python -m app.cli admin
EMAIL` на сервере, поскольку при развёртывании администраторов нет). Каталог в
обоих состояниях обязан оставаться выходом: баннер `#active-trip` и ссылка
«Продолжить поездку» на карточке занятой машины.

## Граница готовности

Веб-сценарии работают с локальными данными. Банк, проверка документов, телематика и замки автомобилей не подключены. Итоги поездки являются расчётом, а не кассовым чеком. Контейнерный запуск, реальный HTTPS и интеграции требуют проверки в выбранной инфраструктуре до обслуживания реальных поездок.
