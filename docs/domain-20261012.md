## Настройки

- Caddy обслуживает поддомен через HTTPS и получает сертификат Let's Encrypt
  автоматически. Проверенный сертификат содержит SAN `podkletnov.uwu.nz` и
  действует до 10 января 2027, 15:34:29 Europe/Volgograd; обновлением управляет Caddy.
- HTTP поддомена перенаправляется на HTTPS (308). HTTPS старого IP перенаправляется
  на поддомен (301), сохраняя путь и query-параметры. Сертификат IP сохранён для
  безопасного перехода со старых ссылок.
- `ALLOWED_HOSTS` в `/etc/drive-carsharing/app.env` дополнен точным именем поддомена.
  Остальные настройки сохранены. Перезапущено только приложение каршеринга;
  его код и данные не заменялись, миграции не выполнялись.
- Статика по-прежнему отдаётся Caddy напрямую из `current/app/static` с проверкой
  кэша. API и HTML идут на прежний `127.0.0.1:18080`.

При получении сертификата системный резолвер VPS вернул DNSSEC `missing-key` для
Let’s Encrypt и нового поддомена. Рабочие ответы подтверждены отдельно через
Cloudflare и Google DNS. Для proxy создана собственная конфигурация:

```ini
# /etc/systemd/system/drive-carsharing-proxy.service.d/10-dns.conf
[Service]
BindReadOnlyPaths=/etc/drive-carsharing/proxy-resolv.conf:/etc/resolv.conf
Environment=GODEBUG=netdns=go
```

`proxy-resolv.conf` использует `1.1.1.1` и `8.8.8.8`. Это отдельное представление
файла внутри службы, предусмотренное [systemd](https://github.com/systemd/systemd/blob/main/man/systemd.exec.xml).
Проверка через `nsenter` подтвердила новые адреса только внутри proxy. Контрольная
сумма системного `/etc/resolv.conf` не изменилась. Перезапущен только proxy;
настройки системного DNS, Gemini и TLS-хранилище сохранены.
